# Human-like Writing / 인간스러운 글쓰기 (Distilled)

영어·한국어 문장을 자연스럽게 다듬되, 원문의 사실과 필자 고유의 목소리를 보존한다.

## 기본 계약

- 주장, 고유명사, 숫자, 날짜, 부정, 조건, 인과관계, 책임 주체를 바꾸지 않는다.
- 기계적인 리듬, 과장, 번역투, 모호한 수식어를 줄이되 원문의 개성·감정·전문 용어를 평평하게 만들지 않는다.
- AI 탐지 우회나 인간 작성 판정을 약속하지 않는다. 목적은 더 정확하고 읽기 좋은 편집이다.
- 기본 작업에서는 외부 CLI, API, MCP, 별도 모델 호출, 점수 계산을 사용하지 않는다.

## 워크플로우

1. **목적과 목소리 고정**
   - 문서 종류, 독자, 격식, 필자의 기존 말투를 파악한다.
   - 사용자가 원하는 길이와 출력 형식을 우선한다.

2. **의미 앵커 추출**
   - 수정 전에 핵심 주장, 수치, 고유명사, 부정·조건, 원인과 결과를 짧게 내부 확인한다.
   - 자기소개서·계약·보고서처럼 위험이 큰 글은 문단별 앵커를 확인한다.

3. **구조 먼저 진단**
   - 문단 길이가 지나치게 균일한지, 모든 내용을 체크리스트처럼 빠짐없이 나열하는지, 매번 문제→교훈으로 너무 반듯하게 닫는지 본다.
   - 소제목·삼단 목록·요약 문단이 글의 목적보다 형식을 앞세우면 줄인다.

4. **문장과 어휘 다듬기**
   - 추상적인 평가 대신 구체적 행동·사실·결과를 쓴다.
   - 영어는 단순한 `is`, `are`, `has`를 억지로 피하지 않는다.
   - 한국어는 불필요한 영어 병기와 직역 조사를 제거한다.
   - 구체적인 패턴 확인이 필요할 때만 해당 언어 reference의 관련 절을 부분 조회한다.

5. **의미와 과잉 교정 검증**
   - 수정 전후의 앵커를 대조한다. 빠진 수치, 뒤집힌 부정, 약해지거나 강해진 단정, 바뀐 책임 주체가 있으면 원문을 복원한다.
   - 이미 자연스러운 문장은 고치지 않는다. 변화량보다 문맥 적합성과 필자다움을 우선한다.

## 작업 강도

- **기본 교정**: 한 번의 구조·문장 교정과 한 번의 의미 검증으로 끝낸다.
- **감사 모드**: 사용자가 진단만 원하면 가장 영향이 큰 문제 3~7개만 제시하고 재작성하지 않는다.
- **심층 검수**: 긴 문서나 제출 문서에서만 문단별 의미 앵커를 다시 확인한다. 별도 도구나 추가 모델 호출은 사용자가 요청한 경우에만 고려한다.

## 출력

- 사용자가 형식을 지정하면 그대로 따른다.
- 기본값은 `다듬은 최종본`과 수정 핵심 2~3줄이다.
- 사용자가 최종본만 원하면 설명 없이 최종본만 출력한다.
